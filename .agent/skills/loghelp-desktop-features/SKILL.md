# LogHelp 桌面功能约束

先读取当前仓库根 `AGENTS.md`，再按任务读取 `.agent/` 对应规则；沿用会话中已有构建授权，不扩展提交、推送或发布范围。用户明确约束优先。

## 跨平台是实现范围

- 默认覆盖 Windows、macOS、Linux，并考虑 amd64/arm64。除非用户明确缩小范围，不得因当前开发机是 Windows 而交付单平台功能。
- 业务、ADB 协议、视频生命周期和渲染优先共用；操作系统能力通过平台文件或清晰接口实现。其他平台只返回“不支持”、空实现或 TODO，不能算跨平台完成。
- 保持 `CGO_ENABLED=0`。选择系统库、纯 Go 运行时绑定或外部解码器时，说明每个平台的依赖、查找方式、架构匹配及分发路径。动态库 ABI 必须做版本检查；共用后备路径也要能实际执行。
- 依赖应固定版本并校验完整性，构建指纹覆盖内嵌资源。架构无关的 Android 服务不得只嵌入 Windows 构建；补齐相关构建入口及依赖说明。

## 设备投屏和截图

- 用户要求类似 Running Devices 的流畅投屏时，采用持续视频流；定时执行 `screencap` 只能作为截图或明确的低频预览，不能冒充视频投屏。
- 只保留最新帧，复用纹理/像素缓冲；视频更新不触发整个日志工作区重绘。触摸按下、移动、抬起应通过持续控制连接发送，避免每次操作启动 ADB 子进程。
- 目标设备固定绑定；关闭、重连、旋转、失焦和弹窗妥善结束手势。取消会话要释放解码器、进程和连接，仅清理本会话创建的转发和临时服务文件；应用退出需给清理工作完成机会。
- 保存与复制是两个可选择的截图操作，保留原始分辨率。图片剪贴板必须写图片数据，不写文件路径或 Base64 文本：Windows 发布 PNG/标准位图，macOS 使用系统图片剪贴板，Linux 覆盖 Wayland 与 X11 的 `image/png`。
- 依赖缺失、抓屏/解码/写文件/剪贴板失败需给出中文原因和可执行的处理方式；失败不得显示“已复制”或“已保存”。

## 验证和报告

- 遵循项目手动验收规则，不新增或自动运行测试。按修改范围串行验证目标平台模块编译；同一份源码成功构建后，不因 review 重复编译。
- 区分模块编译、桌面构建、真实设备视频、GUI 显示、输入交互、图片格式/粘贴和资源清理。没有目标系统，不声称其运行或交互已通过。
- 配置“最高 60 FPS”不等于实际 60 FPS。记录真实帧数、采样时长、首帧时间和分辨率；不同屏幕内容/设备负载的记录不能冒充严格性能对比。
- 把实际证据和未验收项写入 `docs/manual-validation.md`，必要时更新使用说明/变更记录；最终交付给出可用产物和明确的剩余验证范围。

# LogHelp 代码同步

本项目代码更新默认使用 rebase；用户已授权该方式，后续同类更新无需再次询问。遵循用户当次明确指令，不扩大到其他仓库或外部操作。

## 同步流程

1. 确认当前分支、工作区与暂存区、上游及远端。没有上游、处于 detached HEAD 或已有未完成的合并/rebase 时，说明阻塞，不擅自选择分支或终止其他操作。
2. 有未提交改动时，使用带说明的 `git stash push --include-untracked` 保存并记录 stash 的完整对象 ID；原暂存状态一并保留。备份失败则停止，不丢弃改动，不自动创建业务提交。
3. 获取当前上游对应远端更新，对当前分支执行 `git rebase` 到已确认的上游；不切换分支、不改写其他分支、不推送。
4. rebase 成功后，用记录的 stash ID 执行 `git stash apply --index` 恢复改动。保留备份直到确认恢复完整；发生冲突时不使用 `stash pop` 或丢弃备份。
5. 对只涉及文本拼接或清晰接口适配的冲突，可在保留双方意图的前提下解决；无法判断业务取舍时停止并报告冲突文件、备份和当前状态，不选择整份 ours/theirs 覆盖。rebase 本身的冲突未解决前，不恢复 stash。
6. stash 恢复冲突解决后，仅调整本次恢复涉及文件的索引，使其回到更新前的暂存/未暂存状态；不把用户原本未暂存的改动留为已暂存，不影响无关文件。确认分支与上游差异、工作区状态和本次冲突标记，简短报告结果及保留的备份。

## 范围边界

- 纯代码同步只做必要 Git 操作与冲突处理；不自动进行功能变化审查、代码 review、回归分析、静态检查脚本、编译、测试、安装、运行、文档维护、提交、推送或外部通知。用户另行明确要求的工作按其范围执行。
- 不执行破坏性清理、强制重置、强制推送或丢弃改动。权限不足时按工具审批流程申请必要 Git 权限，既有同步授权继续有效。
- 保留所有本地改动与未跟踪文件；忽略文件不纳入 stash，不擅自移动或删除。无法安全恢复原暂存状态时，保留 stash 并如实报告。

# 代码与更新约束

- 修改 Go 代码按现有模块职责划分并执行 `gofmt`；优先复用现有配置、UI 和采集入口，避免为简单功能新增依赖。
- 错误必须有可定位的上下文，向用户显示中文提示；不要吞掉文件写入、网络、进程启动或校验失败。
- 网络检查与下载放在后台，提供超时与失败状态；通过现有线程安全方式向 UI 交付结果，不在绘制循环阻塞网络或文件操作。
- 更新状态、按钮和发布说明在独立弹窗中布局；说明独立滚动，设置页不因检查结果抖动，关闭弹窗后保留未保存设置。
- 同版本修订先以整数比较，不能用字符串排序（例如 `r10` 必须大于 `r9`）。只接受约定的版本、平台、架构及修订附件，避免选择校验文件或其他平台包。
- 下载、解压、SHA-256 校验都成功后才能替换。解压路径限定到临时目录，拒绝路径穿越，不执行附件中任意脚本。
- 替换 EXE 前明确提醒并确认结束采集、录制和终端；备份原 EXE，替换或重启失败时恢复，成功后清理临时文件。不覆盖用户配置、录制和日志。
- 版本和图标修改同时检查窗口标题、主界面、设置页、更新弹窗、EXE 资源和发布说明，避免界面版本与产物版本不一致。
- 遵循根 `AGENTS.md` 的手动验收和构建边界，不因编码指南新增测试。

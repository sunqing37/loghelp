# 更新记录规范

每次提交前，根据本次实际暂存的修改更新根 `CHANGELOG.md`，并与对应改动一起提交。包括文档、辅助脚本及发布流程，不用计划项或工作区无关内容填充条目。

- 沿用根文件的“版本 + 日期”结构；同版本修订增加对应 `rN` 小节，协作规则等维护事项可以增加相应小节。
- 描述实际行为、修复及必要限制；例如“同版本比较修订号”，不要只列文件名或写“优化若干问题”。
- 对外发布时同步 `docs/releases/<版本>.md`，写清产品版本、修订号、下载文件名、升级限制和验收范围。
- 验证只写实际执行结果；把编译、启动、手动交互与更新替换分别记录。详细手动证据维护在 `docs/manual-validation.md`，不要把尚未运行的路径写成已通过。
- 分批提交时每一条记录对应自己的 staged diff。不得用提前写好的宽泛记录覆盖后来不相关提交。
- Release 文案用于用户理解最终发布能力，不把内部调试过程当作发布功能。

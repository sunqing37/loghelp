## Context

项目从空目录开始，目标是提供独立的桌面 Logcat 工具。需求由实时日志查看、多设备、过滤、保存、搜索、设备终端及多标签页组成。用户要求仅使用 Go 编译器，采用 Go + Ebitengine + EbitenUI；不新增自动化测试，验收使用手动场景。核心和界面源码已实现，Windows 完整构建及基础手动验收已完成，其他平台和完整场景仍待验收。

## Goals / Non-Goals

**Goals:**
- 支持 Windows、macOS、Linux 的桌面交互，操作体验接近 AS Logcat。
- 从设备采集到查询、保存、离线查看形成完整闭环，异常不能静默丢失。
- 标签页可以独立分析同一采集流，显示暂停或过滤不干扰录制。
- 各服务具有可取消的生命周期；退出时释放本工具启动的子进程和文件句柄。

**Non-Goals:**
- 第一版不提供分屏、无线配对向导、崩溃自动聚合、书签、任意文本格式解析或云同步。
- 不保证断线期间或设备日志缓冲区已覆盖的数据能够补回。
- 不新增自动化测试；桌面全量构建在人工确认后执行。

## Decisions

### 1. 仅使用 Go 编译器的桌面界面

采用 Go + Ebitengine v2.10.5 + EbitenUI v0.7.3。Ebitengine 从 2.10 开始在 Windows/macOS/Linux 桌面平台全部支持 CGO_ENABLED=0；Go 最低版本为 1.25。平台 API 通过 PureGo 调用，不再要求 C 编译器或开发头文件。依据 [官方发布说明](https://ebitengine.org/en/documents/2.10.html)，Linux 运行仍依赖系统图形库和桌面会话。

EbitenUI 提供按钮、文本框、标签导航和模态窗口。界面使用统一的深浅色语义配色、6px 控件圆角、8/12/16px 间距和独立的标题/正文/辅助字体。所有共用文本与横排组件按垂直中心对齐，按钮/输入统一为 36px，输入文本内边距与表格行内位置按实际字体高度计算，避免字号不同导致贴顶和错位。Windows 界面优先使用微软雅黑，日志使用 Consolas（其他平台尝试系统等宽字体，缺失时回退 Go Mono），中文使用字体回退；窗口标题栏跟随主题，品牌图标由 Go 绘制。

布局分为顶栏、设备/来源侧栏、日志分析工作区与状态栏。主区包含标签、过滤/搜索、视图工具、固定列头的单行日志表格、原文详情；日志仅绘制可见行，长字段省略、选中行标记清晰，窄窗口支持横向浏览列。新建和标签管理、低频日志操作与需确认的设备操作分别收纳到菜单。离线侧栏显示文件来源，终端固定绑定设备。最小窗口 1000×720，初始 1440×900。

偏好设置按连接、阅读、录制、缓存/终端及快捷键分组；主题、布尔值与可见列使用可点选控件，保存操作固定在弹窗底部，滚动内容不遮挡保存按钮。弹窗按内容调整尺寸并提供背景遮罩与 Esc 关闭。后台工作通过有界任务队列回到界面线程。

全部应用源码使用 Go，无需网页前端。文件/目录选择采用应用内浏览器；终端使用 vt10x + ADB Shell-v2；离线结果固定大小分页，查询扫描完整来源并提供取消与进度。

三个桌面平台 amd64 的 core/ui 模块已在 CGO_ENABLED=0 下编译通过，不使用排除平台功能的 ci 标签。桌面入口的依赖检查均无活动 Cgo 包；Windows 已获确认完成 EXE 链接、启动、真实采集、查询、录制/离线及终端连接基础检查，macOS/Linux 实际 GUI 和终端验收仍待进行。

### 2. ADB 发现与设备身份

优先使用用户已配置且验证成功的绝对路径，未配置时使用 Go 的 PATH 查找。配置接收可执行文件路径，也允许选择 platform-tools 目录后自动定位 adb/adb.exe；校验 `adb version`，展示最终路径和版本。已配置路径失效时给出修复提示和重新使用 PATH 的入口，不悄悄切换版本。

所有设备操作显式传递 `-s <serial>`，通过参数数组调用可执行文件。不自动执行 `adb kill-server`，避免干扰其他工具。设备监控失败时使用有间隔的重新枚举并退避。日志会话的身份包含设备序列号、采集配置和连接代次，防止 PID 重用或设备重启造成错误关联。

### 3. 共享采集与状态分离

每个设备及采集配置组合共享一个 Collector，标签页是订阅者，录制器是独立订阅者。配置包括缓冲区及输出格式；配置不同的采集不能强行合并。默认选 main/system/crash，在实际设备上探测可用选项；设备不支持某缓冲区时提示并允许调整，不清空设备缓冲区。

采集流进入解析器，分发至显示环形缓存和文件写入器。显示暂停仅冻结视图快照；缓存和文件写入继续。停止共享采集前显示受影响的标签页和录制，用户可选择只关闭当前订阅或停止整个共享会话。清屏记录当前标签页的显示起点；清空设备缓冲区使用不同操作。

断线保留已采集数据，记录主机时间和中断标记，并按序列号重连。从上次时间边界尝试续取，不激进去重以免误删真实重复日志，界面明确提示边界重复及缺口风险。进程映射按连接代次、进程名称及观察时间生效，修正时钟偏差后不将当前映射套到较早缓冲区日志。包名获取失败或不能确认时显示未知。录制条目保存当时有效的包名与进程名，离线不依赖当前设备。

### 4. 日志与查询模型

日志条目至少包含会话 ID、递增序号、设备、缓冲区、设备时间、主机接收时间、PID/TID、级别、Tag、消息及原始文本；包名和进程名为可缺省的补充字段。保留多行消息边界，解析失败的文本作为未解析条目保留并显示。系统生成的连接事件与设备原始日志区分。

过滤在 Go 中编译为语法树，支持 tag/package/process/message/line/level/age，另支持 pid/tid 和绝对时间范围；文本默认不区分大小写，可切换。字段文本按包含匹配，应用选择器按包名精确匹配。支持 `-`、`~`、`&`、`|` 和括号；同键非否定条件隐式 OR，其他条件隐式 AND；显式逻辑中 AND 优先于 OR。纯文本词项按消息包含匹配，多词隐式 AND，带空格短语使用引号。

正则使用 Go RE2 语义；不支持的回溯/环视须明确报错。输入无效时保留最后有效查询，显示错误位置，不显示错误条件已生效的状态。第一版不实现 package:mine、is:crash/is:stacktrace 等特殊查询。支持的兼容范围及示例可直接在帮助中查看，参考 [AS 查询说明](https://developer.android.com/studio/debug/logcat?hl=zh-cn)。

搜索在过滤结果内执行，返回条目 ID 与 Unicode 匹配范围，分页加载并高亮；用户可在独立上下文面板查看命中前后未过滤条目。实时 age 使用主机当前时间，离线 age 使用最后一条可解析设备时间为固定锚点；显示锚点和时区，设备时间异常时提示。绝对时间范围为起点包含、终点不包含。

### 5. 文件格式和录制生命周期

会话目录按设备/日期/会话组织，使用 UTF-8 JSONL 分段保存原始文本、结构化字段及会话事件，manifest 记录格式版本、序列号、设备信息、时区、片段和进程映射。原始字节不能无损解码时额外保留编码后的原始字节。第一版可导入本工具会话和标准 threadtime Logcat 文本；其他格式先以未解析条目展示并提示字段过滤限制。

默认每段约 100 MiB，超大单条不拆开，允许该段临时超过阈值。新建录制默认目录额度 2 GiB，达到额度后停止该目录新增录制并提示，实时查看继续；默认不自动删除旧日志。用户可启用保留天数/容量淘汰，只清理本工具生成、非录制中且未标记保留的会话，默认建议保留 7 天。支持暂停/继续录制，暂停间隔记为会话事件。

录制从启动写入的边界开始，不默认回填显示缓存；导出单独支持当前过滤结果和选中内容。用户必须先选择有效目录，验证失败不进入录制状态。文件 I/O 使用有界队列：写入失败或持续跟不上时停止录制，显示最后成功写入位置和未写入数量，不无限占用内存、不静默丢弃。允许用户选择新目录恢复为新片段。

故障恢复入口在录制管理及原日志页，目录只作用于本次恢复。等待旧写入器结束后确定最终持久化边界，新建会话在 manifest.recovery 和首段事件中关联旧目录、最后持久化序号/接收时间、已确认未写数量、故障原因及故障/恢复时间；在共享采集的发布边界串行写入恢复事件，manifest.first_seq 记录首个写入的非零原始序号。不回填间隔。无视图时保留故障会话供管理；显式停止可释放，恢复初始化失败仍保留旧故障。并发停止使正在准备的恢复失效，不会在停止后重新发布录制。

离线读取按分页与懒加载索引查询，不把全部文件载入内存。大范围搜索可取消，显示进度；重开会话不依赖 ADB。损坏尾行保留可读部分，并明确标出损坏位置。导出为用户指定文件，不覆盖原始录制文件。

首次流式读取建立稀疏文件位置索引，保存原始序号、文件/字节偏移、物理行号、块内最大时间及录制原始序号范围。检查点从每 512 条一个开始，超过 8,192 个时两两合并并扩大间距。过滤/搜索首次按完整快照懒建同样有界的结果位置及匹配累计索引，每个来源最多缓存两组条件，键包含大小写、正则及应用限制；后续分页、前后匹配和时间跳转只扫描相关块。上下文直接按来源序号 seek。索引不持久化，不保留全量 Entry；文件按打开时长度限读，活动录制后续追加不改变 age 锚点。源文件替换、缩短或等长修改时拒绝复用并提示重开；超长行跳过过程中也检查取消。

### 6. 标签页、设置和快捷键

每个实时标签页独立保存设备序列号、采集配置、过滤、搜索、显示起点和滚动状态，离线标签页保存文件引用；全局保存字体、主题、缓存上限、录制偏好与 ADB 配置。关闭最后一个日志标签页仍允许录制继续，录制管理入口显示后台任务并可停止。退出应用时终止采集和录制，不提供退出后后台服务。

启动恢复标签页和偏好，可恢复设备日志订阅；不自动恢复录制或执行 Shell。丢失的设备/文件保留占位和定位入口。默认快捷键：Ctrl/Cmd+F 搜索，F3/Shift+F3 匹配导航，Ctrl/Cmd+L 聚焦过滤，Ctrl/Cmd+T/W 新建/关闭页，Ctrl+Tab/Shift+Ctrl+Tab 切换页；暂停和跳到末尾通过工具栏及可配置快捷键提供。终端有焦点时优先处理终端按键，Esc 退出搜索/编辑焦点，不覆盖终端 Ctrl+C。

### 7. 交互式设备终端

终端固定绑定设备序列号；切换日志标签页不改变目标。Go 通过配置的 ADB 启动本机服务，再直接使用 Shell-v2 的 PTY 帧协议传递输入、ANSI 输出、Ctrl+C 和尺寸变更，不通过宿主 Shell 拼接命令。默认 TCP ADB 服务及相关环境变量受支持，非 TCP 自定义套接字明确报错。仍需在目标平台完成终端运行验收；单次命令执行不能替代交互终端验收。断线后由用户触发重连，不重放历史命令。

命令历史只在本机保存显式提交的命令，可关闭、清除；不记录每次按键。Shell 标签页关闭时终止相应子进程，日志采集继续。

### 8. 容量和手动验收目标

显示缓存默认限制为 200,000 条或 64 MiB 估算文本与字段大小，任一达到时淘汰旧条目；对单条大消息保留原始记录，显示端采用展开/分页。内存预算除日志缓存外还计入队列、索引与暂停快照，暂停快照同样有界。界面按可见行绘制，实时查询约 600 ms 合并更新，渲染可见行和少量预加载行。

绘图复用一张工作区画面，输入和查询结果变化时立即重绘，静止时以约 250 ms 周期更新光标等状态。输入框的遮罩在控件局部缓冲中绘制，避免每个输入框分配两张整窗纹理；不可见输入不建立缓冲。关闭标签清除数组尾部和结果/暂停快照引用；进程名独立复制，避免日志字段引用整份 `adb ps` 轮询输出。无过滤结果共享不可变快照指针数组，数据未变化或静止视图复用查询结果，`age` 条件仍定期按当前时间重算。字体源在设置变更时复用。

可按需启用本地 Go 堆/累计分配、GPU 纹理估算与进程工作集采样；诊断默认关闭且不开放网络端口。Windows 后台采样使用独立配置及不获取焦点的窗口，并支持保持正常 GC，以区分对象保留、临时分配和图形资源开销。验证记录与局限另见 `docs/memory-profiling.md`。

建议验收基线：记录设备、操作系统、硬件和平均行长，在单设备约 5,000 行/秒、平均 300 字节、持续 10 分钟的手动压力场景下，内存趋稳、界面仍可导航、录制没有未解释的丢失。这个数字是目标而非现有能力声明，实施后报告实测；设备供给不足时使用标明来源的本地回放。

## Risks / Trade-offs

- ADB 和设备 Logcat 的参数、权限存在差异 → 按设备探测；无权限字段显示未知，不假设包名总能获取。
- 设备断线、重启、时钟回拨或日志缓冲区覆盖 → 分段标记时间与连接代次；不将“自动重连”表述为“保证无丢失”。
- Ebitengine 图形、EbitenUI 控件和 VT 终端及桌面打包存在平台差异 → Go 模块先做兼容检查，完整构建在人工确认后进行，实际 GUI 结果另行记录。
- 显示缓存不是无限历史 → 界面显示范围和淘汰计数，提供打开录制入口；过滤及搜索注明来源范围。
- 离线文件没有进程映射时无法完整包名过滤 → 保留未知字段并提示，不从当前设备推断旧会话。
- 大文件搜索、磁盘慢写和异常超长日志 → 有界队列、可取消后台查询、分页展示，失败时给出可恢复状态。

## Migration Plan

从空工程分阶段实施：先 ADB/PTY 可行性验证，再采集和查询，再录制和离线，最后完善界面及三平台手动验收。配置和文件均带版本；不兼容版本明确提示，不直接改写原始日志。回退只替换应用版本，保留录制文件；任何全量构建或安装包构建在执行前按项目约定人工确认。

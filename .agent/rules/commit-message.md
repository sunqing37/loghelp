# 提交规范

提交信息包含类型、中文模块、描述及问题单号，类型覆盖功能、修复、文档和维护工作。

```text
[type]（模块）描述「单号或无」

[问题原因]
已有问题写已确认原因；新增功能或规范写需求背景。

[解决方式]
说明实现方式及行为变化。

[影响范围]
说明涉及入口、模块、资源或发布产物。

[验证情况]
仅列实际执行及结果，注明未执行的关键验收。
```

| type | 适用范围 |
|---|---|
| `feat` | 用户可见新功能 |
| `fix` | 已确认问题修复 |
| `modify` | 现有功能调整或重构 |
| `add` | 新增辅助工具、资源或配置 |
| `docs` | 文档、协作规范与操作说明 |
| `chore` | 依赖、构建与仓库维护 |

示例：`[fix]（版本更新）识别同版本修订并提示替换「无」`、`[docs]（协作规范）补充发布流程与提交约定「无」`。

## 提交前

1. 检查当前分支、工作区、暂存区及 upstream，保护无关修改。
2. 在已有同步授权范围内 fetch，按当前分支与 upstream 核对远端差异。只在确有更新时选择安全同步方式，不自动强推、清理或 stash 他人修改。
3. 基于本次实际提交范围更新 `CHANGELOG.md`，参见 `changelog.md`。
4. 执行 `git diff --check`，明确暂存文件；不要无差别 `git add .` 纳入日志、临时文件或本地配置。紧密相关代码与发布元数据一起提交，不相关目标可独立拆分。
5. 标题保持单行，正文四项简洁但有实际内容。不虚构验证结果，不自动追加 AI 工具的 `Co-authored-by`。用户明确要求的真人共同作者署名可以保留。

## 安全提交

AI 统一用脚本传递 Git 参数和 UTF-8 正文文件，不拼接 shell 命令：

```powershell
python -X utf8 .agent/scripts/git-commit.py --file artifacts/commit-message.txt
python -X utf8 .agent/scripts/git-commit.py --check
```

脚本通过 Python 参数数组调用标准 Git 提交，保留 Git hooks、签名及正常提交语义。脚本检查标题、四段正文和自动 AI trailer，且只提交已经暂存的文件，不自动 stage、同步或 push。它不会自动改写已发布提交。

如果需要更正本会话新建且未推送的最新提交，可使用 `--amend-unpushed`；脚本在 HEAD 被远端分支或标签引用时拒绝执行。使用前确认该提交属于本次任务，没有其他人的改动。

提交后核对新 commit 的正文和范围，再按用户授权推送。已推送历史禁止为补正文自动 amend / rebase / force-push。发布标签规则参见 `../workflows/github-release.md`。

# LogHelp 内存剖析与优化（2026-10-13）

## 已确认的原因

最大的界面开销来自 EbitenUI 0.7.3 的 `MaskedRenderBuffer.Draw`：它按传入画面的大小创建两张遮罩纹理。原有每个 TextInput 都收到完整的工作区画面，因此一个 36px 高的输入框也会建立两份整窗缓冲；设置中不可见的输入框原先也参与绘制。弹窗和工作区重建会进一步推高图形资源峰值。64 MiB 的日志缓存限制不包含这些纹理、图形驱动、字体和查询对象。

Go 堆还确认 `ADB.Processes` 返回的进程名是整份 `adb ps` 输出的子串，日志引用进程元数据后，会保留多个历史轮询的大字符串。原版 420 秒堆快照中，这条调用链仍保留约 5.24 MiB。关闭最后一个标签时，数组尾部也可能继续引用关闭页面及其日志快照。

逐帧重新绘制所有控件、测量日志文字，加上每 600ms 的全量查询，造成大量临时分配。原版累计分配会达到数 GiB，这个累计数不代表同一时刻全部占用，但会增加回收和内存峰值压力。

## 修改

- 输入框在自己的局部缓冲中绘制，恢复工作区坐标后合成到原位置；不可见输入不建立缓冲，缓冲尺寸改变时释放旧图像。
- 工作区复用一张画面，键鼠和查询结果变化时立即重绘，其余时约每 250ms 更新一次光标等内容。字体源在设置变更时复用。
- 无过滤结果共享不可变快照指针数组；数据未变化、暂停或停止视图复用结果。`age` 条件仍按当前时间重新计算。
- 进程名独立复制，关闭标签清空尾部、结果和暂停/停止快照引用。
- 增加默认关闭的本地堆、累计分配、GPU 纹理和进程采样；后台诊断使用独立配置，不获取窗口焦点，不处理键鼠输入，结束自动退出。

## 设置窗口对照

同一最终 EXE、同一设备和缓存配置、1440×900 工作区、相同设置页面，仅切换 `-LegacyInputs` 复现原来的整窗输入缓冲。两组各采样 120 秒，统计第 20–115.5 秒；使用正常 GC，没有诊断强制 GC。记录中的场景始终为“偏好设置”，`focused=false`。

| 指标 | 原缓冲方式 | 局部缓冲方式 |
| --- | ---: | ---: |
| GPU 纹理估算 | 439.12 MiB | 89.37 MiB |
| 工作集平均值 | 814.83 MiB | 470.50 MiB |
| 工作集最大值（统计区间） | 828.74 MiB | 477.89 MiB |
| 私有内存平均值 | 839.32 MiB | 492.78 MiB |

GPU 纹理估算减少约 79.6%，工作集平均值减少约 42.3%。GPU 纹理估算不等于图形驱动的完整占用，不能简单与 Go 堆相加作为进程内存。进程总占用包含缓存日志、字体、Go 堆和系统绘图资源，修复后仍会高于 64 MiB。

原始数据位于 `artifacts/memory-settings-control/` 和 `artifacts/memory-settings-stable/`，各有 `memory.jsonl`、`process.csv`、堆快照与应用内部渲染的 `workspace.png`。没有读取桌面或其他应用的窗口。

## 十分钟主界面采样

最终固定场景采样位于 `artifacts/memory-main-stable/`，持续 600 秒，进程退出码为 0。采用正常 GC，工作区始终 1440×900、无弹窗、`focused=false`；输入框记录的最大尺寸为 965×36。使用真实设备自然日志流，不是固定速率回放。

| 指标 | 实测 |
| --- | ---: |
| 第 20.1–597.8 秒工作集范围 | 396.66–414.96 MiB |
| 该区间平均工作集 | 402.88 MiB |
| 最后约五分钟工作集范围 | 398.22–401.73 MiB |
| 最后约五分钟平均私有内存 | 422.89 MiB |
| 全程 GPU 纹理估算 | 57.87 MiB，未发生增长 |
| 最后约五分钟 Go 累计分配速率 | 2.88 MiB/s |
| 活动期 goroutine 数量 | 10，退出回落到 2 |

Go HeapAlloc 会随正常 GC 波动（统计区间约 105–210 MiB），工作集在最后五分钟基本稳定；未将“自然 GC 波动”误判为对象泄漏。进程退出后，该采样进程及其 ADB 日志子进程均已不存在，stderr 为空。进程名轮询的大输出保留在最终堆采样中也已消失。

此前一轮后台采样中途出现了弹窗/场景变化，并捕捉到约 963 MiB 的 GPU 高峰，不能将那轮作为固定主界面已通过的证据；因此增加键鼠隔离和场景/尺寸记录后重新采样。新的后台诊断不处理键鼠事件，也不改变系统光标，避免其他桌面操作影响诊断场景。以上十分钟结果不代表所有交互、所有设备和所有平台都不会发生峰值。

Windows 11 家庭版 10.0.26200，Intel Core Ultra 7 255H，32 GiB 内存，Intel Arc 140T 驱动 32.0.101.7026，Go 1.26.2，CGO_ENABLED=0，真实 Samsung SM-S921B 日志流。缓存配置为 200,000 条 / 64 MiB 估算字段。

没有新增自动化测试。所有编译在代码变更后进行，并等待其他构建完成；源码未改时未重复构建。实际自然日志采样不是 5,000 行/秒的回放压力验收，OpenSpec 的该项仍保留未完成。

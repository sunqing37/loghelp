# LogHelp 0.0.4

产品版本 `0.0.4`，内嵌修订号 `0`。源码标签 [v0.0.4](https://github.com/sunqing37/loghelp/tree/v0.0.4)。本次从 `0.0.3` 升级，新增指定设备应用安装；历史 Release 和附件保留。

## 安装应用到指定设备

- 顶部「安装应用」打开安装窗口，可主动选择在线目标设备，通过系统文件对话框选择应用，或将安装包拖入主窗口/安装弹窗；支持多选，一次最多 128 个文件。
- 支持 APK、多个 APK / split APK、AAB、APKS、XAPK、APKM 及未加密 `.multi-apk` ZIP。多个 APK 按包名与版本归组，同一应用的 base 与 splits 一起安装，不同应用依次安装；归档分包按设备支持的 ABI 筛选，保留语言和密度资源。
- XAPK 的 OBB 在 APK 安装后复制到目标设备 `/sdcard/Android/obb/<包名>/`。OBB 校验包名，复制失败会单独提示，不将应用已安装误报为整个任务成功。
- 安装始终绑定所选设备，切换日志页不会改变目标。窗口显示阶段、结果与中文错误，支持取消；关闭弹窗后继续后台安装，可重新打开查看。签名冲突、低版本、设备安装限制及存储不足提供处理提示。

默认覆盖安装并保留应用数据，需签名一致且版本允许；不会自动卸载、降级或绕过设备限制。任务最长 30 分钟，取消、断连或批次后续失败不会回滚已安装应用或已写入的 OBB，需检查设备实际状态。同一应用仅选择一个版本、一份基础包及其完整 splits。旧版加密 APKM 需先用来源工具导出未加密安装包。

### AAB / 官方 APKS 依赖

包含 `toc.pb` 的官方 APKS 和 AAB 使用 [官方 bundletool](https://developer.android.com/tools/bundletool) 选择或生成设备匹配的 APK。需另行准备 Java（建议 JDK 17+）及 [bundletool-all JAR](https://github.com/google/bundletool/releases)，在「安装工具设置」中选择路径；不自动下载依赖或修改 PATH。

Java 路径留空时使用 `JAVA_HOME/bin/java` 或 PATH；bundletool 留空时依次读取 `BUNDLETOOL_JAR`、程序旁 `tools/bundletool.jar`。APK 和普通 ZIP 分包归档只需现有 ADB，无需 Java。

AAB 默认由 bundletool 使用调试签名，需可用的调试签名密钥，通常无法覆盖商店正式签名的版本。如需正式签名覆盖，请先在外部用原签名生成 APKS，再选择该文件安装。

## 升级与运行依赖

Windows x64 便携版和当前用户安装版可从设置页「检查更新」，下载匹配的 ZIP、校验 SHA-256 后替换并重启，保留配置和录制文件；Setup 单独提供下载。Windows ARM64、macOS、Linux 手动下载对应附件。升级前保存设置；手动替换或安装前退出旧程序。

本次为产品版本升级 `0.0.3 → 0.0.4`，旧版可通过版本号识别，不依赖同版本修订比较。

ADB 需另行准备。Windows x64 内嵌 scrcpy 服务与 FFmpeg 解码库；其他架构/平台投屏需匹配架构的 FFmpeg（可执行程序需 5+，原生动态库需兼容 FFmpeg 7）。Linux 需要图形桌面及系统图形库，文件选择需 zenity/matedialog/qarma，图片剪贴板需 wl-clipboard 或 xclip。详见包内 README 和 `docs/mirror-runtime.md`。

## 验收范围

用户已反馈安装功能手动测试通过；review 补齐异常 manifest 字符串池解码预算。编译、Windows 启动、版本显示、发布包和更新识别的实际记录见 [手动验收记录](https://github.com/sunqing37/loghelp/blob/v0.0.4/docs/manual-validation.md)。不推定用户反馈覆盖所有格式、异常路径或其他系统交互。

六平台采用 CGO=0 完整桌面构建，包内记录源码 commit、版本、修订和程序 SHA-256，Unix 程序保留执行权限。macOS、Linux 和 Windows ARM64 由 Windows 主机交叉构建，尚未完成对应系统的运行验收；本次未重新执行全部设备功能、安装器实装及自动更新替换回滚流程。
